# «Скачать приложение»: PWA с фоновым воспроизведением + APK по желанию

## Что изменилось и почему

**Раньше** плеер играл звук через сырой Web Audio API
(`AudioBufferSourceNode`) — такой звук браузеры глушат, как только вкладка
уходит в фон/экран блокируется, и на экране блокировки ничего не
показывается.

**Теперь** (`lib/audioEngine.ts`) воспроизведение идёт через настоящий
`<audio>`-элемент + `navigator.mediaSession` — это единственный API,
которому мобильные ОС официально разрешают:
- играть звук, пока экран заблокирован или вкладка/приложение свёрнуто;
- показывать плашку с обложкой, названием и кнопками play/pause/next/prev
  на экране блокировки и в шторке уведомлений.

Плюс сайт стал устанавливаемым PWA (`public/manifest.webmanifest`,
`public/sw.js`, иконки в `public/icons/`) — это и есть замена «вебвью»
без App Store/Google Play: иконка на главном экране, отдельное окно без
адресной строки браузера.

## Куда класть файлы

```
index.html                          — заменить (добавлены manifest/иконки)
main.tsx                            — заменить (регистрация service worker)
public/manifest.webmanifest         — новый файл, в public/
public/sw.js                        — новый файл, в public/
public/icons/*.png                  — новая папка с иконками, в public/
lib/audioEngine.ts                  — заменить
hooks/useInstallPrompt.ts           — новый файл, новая папка hooks/
components/InstallInstructionsModal.tsx — новый файл
components/Sidebar.tsx              — заменить (кнопка "Скачать приложение")
App.tsx                             — заменить (подключены обработчики Media Session)
```

Если у вашего Vite-проекта ещё нет папки `public/` — создайте её в корне
рядом с `index.html`; всё, что в ней лежит, Vite копирует как есть и
раздаёт от корня сайта (`/manifest.webmanifest`, `/sw.js`, `/icons/...`).

## Как это работает для пользователя

**Android (Chrome):** в меню сайта появляется пункт «Скачать приложение».
По нажатию — стандартный системный диалог «Установить приложение».
После установки — иконка на рабочем столе, окно без адресной строки,
музыка играет с заблокированным экраном, на экране блокировки — обложка
и кнопки управления.

**iPhone/iPad (Safari):** нативного диалога установки в Safari нет —
по нажатию показывается модалка с 3 шагами («Поделиться» → «На экран
Домой»). Дальше всё работает так же — иконка, полноэкранный режим,
кнопки на экране блокировки.

## Важные ограничения (честно, чтобы не было сюрпризов)

- **HTTPS обязателен.** Service worker и install-промпт не работают на
  `http://`, кроме `localhost`. Если сайт на GitHub Pages/Netlify/Vercel —
  всё ок, там HTTPS по умолчанию.
- **iOS строже к фоновому звуку**, чем Android. В большинстве случаев с
  установленным на "Домой" PWA всё работает (проверено паттерном, который
  используют веб-плееры вроде Spotify Web/YouTube Music), но Apple может
  агрессивнее прибивать вкладку при нехватке памяти — 100% гарантии как у
  нативного приложения это не даёт.
- Кнопка «Скачать приложение» **не показывается**, если сайт уже открыт
  как установленное приложение (проверяется через `display-mode: standalone`).
- Иконки в `public/icons/` — плейсхолдер (белый диск на чёрном, в стиле
  вашего лого). Замените на свои PNG того же размера, если нужен другой
  дизайн.

## Как проверить

1. `npm install && npm run build && npm run preview` (или задеплойте).
2. Откройте собранный сайт **по HTTPS** с телефона.
3. Android: Chrome → меню → должен появиться пункт «Установить
   приложение» (или наша кнопка «Скачать приложение» сработает сама).
4. iPhone: Safari → «Поделиться» → «На экран Домой».
5. Запустите с иконки, включите любой трек, заблокируйте экран — на
   экране блокировки должна появиться плашка плеера с кнопками.

## Если всё-таки нужен именно файл `.apk`

PWA-установка выше даёт тот же результат (иконка, отдельное окно, фоновый
звук), что и APK — без необходимости собирать что-либо нативное. Но если
вам принципиально важен скачиваемый `.apk`-файл (например, чтобы
рассылать его напрямую, а не полагаться на кнопку в браузере), это
делается через **Trusted Web Activity (TWA)** — официальный от Google
способ обернуть PWA в APK. TWA — это, по сути, полноценный Chrome под
капотом, поэтому Media Session/фоновый звук работают так же, как в
браузере, без написания нативного кода.

Кратко (нужен Node.js, Java 11+/Android SDK — не выполняется в этой
среде, только у вас локально):

```bash
npm install -g @bubblewrap/cli
bubblewrap init --manifest=https://ваш-сайт.example.com/manifest.webmanifest
bubblewrap build
```

Bubblewrap спросит имя пакета, задаст ключ подписи (сгенерирует сам при
первом запуске) и соберёт `app-release-signed.apk` — его и раздаёте
пользователям напрямую (Android спросит разрешение на установку из
«неизвестных источников», это нормально при установке не из Google Play).

Подробности и troubleshooting: https://github.com/GoogleChromeLabs/bubblewrap
